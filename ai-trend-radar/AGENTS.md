# AI Trend Radar Codex Rules

이 문서는 `AI Trend Radar` 프로젝트의 헌법이다. Codex는 이 저장소를 열 때마다 이 파일과 `README.md`를 먼저 읽고, 아래 규칙을 기준으로 작업한다.

## 프로젝트 목적

이 프로젝트는 AI 트렌드, AI 뉴스, AI 툴, AI 자동화, AI 부업, SNS 수익화, AI 돈벌이 구조, AI 과장광고/사기성 주장, AI가 일과 돈에 미치는 변화를 인스타그램 콘텐츠 후보로 가공하기 위한 편집국 시스템이다.

계정 방향은 다음과 같다.

> AI 시대에 돈과 일이 어떻게 바뀌는지 가장 쉽게 정리하는 계정

소재 범위는 넓게 가져간다.

- AI TREND
- AI NEWS
- AI TOOL
- AI AUTOMATION
- AI MONEY
- AI SIDE HUSTLE
- SNS 수익화
- AI 콘텐츠 자동화
- AI 부업 현실
- AI 과장광고/사기/착각 해부
- AI가 일과 직업에 미치는 영향
- AI 신기능/신제품/공식 발표
- GitHub/오픈소스 AI 도구
- Product Hunt 신규 AI 제품
- YouTube AI 데모
- arXiv AI 논문 중 일반인에게 흥미롭게 풀 수 있는 것

단, 관점은 좁게 유지한다.

> 이 AI 변화가 일반인의 일, 돈, 자동화, 콘텐츠 수익화, 부업, 업무 방식에 어떤 영향을 주는가?

## Codex 운영 원칙

- 항상 `AGENTS.md`와 `README.md`를 먼저 읽고 작업한다.
- 기존 폴더 구조를 임의로 바꾸지 않는다.
- 파일명은 영문 소문자와 하이픈만 사용한다.
- 공백, 한글, 특수문자가 들어간 파일명을 만들지 않는다.
- 출처 URL을 반드시 보존한다.
- 사실과 후킹 문구를 분리한다.
- 공식 확인되지 않은 내용을 확정 표현으로 쓰지 않는다.
- 모든 후보는 리스크 레벨을 포함해야 한다.
- HIGH RISK 후보는 발행 추천하지 말고 HOLD 처리한다.
- 정치, 투자, 코인, 금융수익 보장, 실존 인물 가짜 발언, 의료/법률 조언은 고위험 주제로 본다.
- 실존 인물이 실제로 말하지 않은 내용을 따옴표로 만들지 않는다.
- "100%", "무조건 돈 됨", "수익 보장", "확정" 같은 표현을 금지한다.
- 제목은 매우 자극적이고 호기심을 유발해야 하지만, 허위 사실을 만들면 안 된다.
- 캡션은 짧게 쓰지 않는다. 반드시 자세하고 유익하고 재밌게 작성한다.
- 카드뉴스는 3~9장으로 유동 구성한다.
- 1장은 항상 썸네일이다.
- 마지막 장은 항상 전환컷 또는 CTA 컷이다.
- 릴스 후보는 관련 영상 자료 링크를 반드시 남긴다.
- 카드뉴스 후보는 사용 가능한 이미지 후보, 참고용 이미지, 생성해야 할 이미지 프롬프트를 분리한다.
- 무단 다운로드/무단 재사용을 하지 않는다.
- 저작권이 애매한 이미지/영상은 `assets/reference/`로 분류하고 직접 사용하지 않는다.
- 이미지 생성 프롬프트에는 텍스트와 로고를 넣지 않는다.
- 이미지 생성 프롬프트는 한국어 텍스트를 얹을 수 있게 충분한 여백을 남기도록 작성한다.
- 작업 결과는 `outputs/daily/`에 날짜별 Markdown과 JSON으로 저장한다.
- 자동 게시 기능은 만들지 않는다.
- 사용자가 명령했을 때만 실행되는 수동 트리거형 시스템으로 만든다.

## 편집 원칙

- 목표는 "많이 긁어오기"가 아니라 "발행 후보로 쓸 만한 자료를 선별하기"다.
- 공식 출처, 커뮤니티 반응, 시각 자료, 한국 독자 관련성을 함께 본다.
- 출처 기반 사실은 `verified_facts`에 넣고, 해석은 `interpretation`에 넣는다.
- 검증이 부족한 내용은 `uncertain_points`에 남긴다.
- 제목 후보는 `General Hook`, `Viral Hook`, `Expert Note Hook` 3단계로 각각 5개씩 생성한다.
- `Expert Note Hook`은 원문 기준 기술 보충용이며, 허위 사실, 수익 보장, 실존 인물 가짜 발언은 금지한다.
- 후보마다 `REELS`, `REELS_FIRST`, `CAROUSEL`, `BOTH`, `HOLD` 중 하나를 추천한다.
- Visual 8 이상, Reels fit 8 이상인 BOTH형 후보는 `REELS_FIRST`로 추천한다.
- 매일 보고서 Summary 상단에 오늘 제작 추천 1순위 릴스, 1순위 카드뉴스, 보류 후보를 먼저 출력한다.
- 후보마다 `source_match_status`와 `fact_check_status`를 포함한다.
- Source Summary와 Source Link 주제가 불일치하면 자동으로 HOLD 처리한다.
- HIGH 위험 후보나 출처가 약한 후보는 자극적이더라도 `HOLD`로 둔다.
- 릴스는 영상 자료 링크, 공식 영상 여부, 사용 가능성 판단, 추천 캡처 구간, 영상 없이 대체 가능한 구성을 남긴다.
- 카드뉴스는 3~9장 구성, 카드별 제목과 본문, 이미지 후보, 이미지 생성 프롬프트, 자세한 캡션을 남긴다.
- 카드 구성에는 실제 카드에 들어갈 문구만 출력하고 내부 설명 문장은 넣지 않는다.
- 캡션은 후보별로 첫 문장, 비유, 현실 예시, 댓글 질문이 다르게 느껴지도록 작성하고, 영어 원문 요약을 그대로 섞지 않는다.
- 보고서에 노출되는 공식 사실, 주의점, Why It Matters는 사람이 바로 읽을 수 있게 한국어 표시를 우선한다.
- 이미지 프롬프트는 후보별 장면, 소품, 조명, 카드별 역할을 구체적으로 설계하고 단순 키워드 치환형 문장을 피한다.
- Final Score는 100점 기준으로 출력한다.
- 모든 후보는 `non_expert_hook`, `plain_language_summary`, `why_people_should_care`, `everyday_example`, `jargon_translation`, `expert_note`를 포함한다.
- 모든 후보는 `scroll_stop_score`, `easy_understanding_score`, `jargon_penalty`를 포함한다.
- 1장 썸네일 제목에는 전문용어를 최대한 쓰지 않고, 모델명/기술명/기업명보다 내 일상, 일, 돈, 콘텐츠에 생기는 변화를 먼저 말한다.
- 1장 썸네일에는 멀티모달, 에이전틱, VLM, 로컬 실행, 오픈 모델, 파운데이션 모델, 월드 모델, 컨텍스트 레이어, 거버넌스, 인프라, 벤치마크 같은 전문용어를 쓰지 않는다.
- Recommended Title은 General Hook 또는 Viral Hook 중 가장 쉽게 이해되고 멈춤이 강한 제목으로 고른다.
- 카드뉴스 기본 구조는 일반인용 8장 흐름을 따른다: 썸네일, 쉽게 말하면, 왜 내 일/돈/콘텐츠와 관련 있나, 실제 사용 예시, 원문 기준 핵심, 조심할 점, 한 줄 결론, CTA.
- 캡션 첫 문장은 일반인이 멈출 정도로 쉽게 쓰고, 쉬운 비유와 현실 예시를 포함한다.
- 전문 보충은 캡션 후반부에 배치한다.

## 금지 사항

- 실제 API 키를 코드나 문서에 넣지 않는다.
- 자동 게시 기능을 만들지 않는다.
- 무단 다운로드 기능을 만들지 않는다.
- 출처 없는 내용을 사실처럼 쓰지 않는다.
- 투자 권유, 정치 선동, 코인 추천, 금융 수익 보장 표현을 만들지 않는다.
- 실존 인물의 가짜 발언이나 가짜 이미지를 만들지 않는다.
- 의료, 법률, 금융 조언을 콘텐츠 후보로 확정하지 않는다.
- 디자인 템플릿을 만들지 않는다. 이 프로젝트는 자료 편집국 시스템이며 디자인 제작 시스템이 아니다.

## 작업 루틴

작업 시작 전:

```bash
git status
```

그 다음:

```txt
README.md와 AGENTS.md 확인
기존 구조 유지
결과물은 outputs/daily/에 저장
출처와 리스크 필드 보존
```

작업 후:

```bash
git status
```

Windows PC와 MacBook을 번갈아 쓰기 때문에 줄바꿈과 파일명 규칙을 지킨다. 파일명은 영문 소문자와 하이픈을 사용하고, 결과물은 날짜별로 관리한다.
